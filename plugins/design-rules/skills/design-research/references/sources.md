# Where to look

Grouped by what each source is *for*. Every URL here was checked; the tag
after it says what an automated fetch gets back:

- **(text)** — returns readable prose. Fetch it directly.
- **(names)** — an image wall. Fetch it for site and studio names, then
  search those names (SKILL.md, Move 1).
- **(blocked)** — answers an automated request with 403 / 429 / silence.
  Reach a specific page through a search engine instead of retrying.

## Juried competitions

The strongest signal: a real, shipped site that a jury argued about.

- **Awwwards** — awwwards.com (names) — Site of the Day / Month / Year,
  Honourable Mentions, plus collections by category and by technique.
  Scored on design, usability, creativity and content, and each entry
  names the studio — which is the query for the case study.
- **The FWA** — thefwa.com (text) — running since 2000, FWA of the Day.
  Historically where the heaviest interactive and WebGL work lands.
- **CSS Design Awards** — cssdesignawards.com (text) — WOTD plus jury
  scores broken out per criterion.
- **Webby Awards** — webbyawards.com (blocked) — broad internet awards,
  judged by the Academy. Categories cover craft, not only sites.
- **D&AD** — dandad.org (text) — Pencils. Brand, graphic and digital
  craft rather than web mechanics; the place to look for a visual idea
  that has never been on a website.
- **Communication Arts Interactive Annual** — communicationarts.com
  (blocked) — long-running juried annual, editorial rather than trend-led.

## Curated galleries

One editor's taste, but real sites that exist and work.

- **Godly** — godly.website (names) — tightly curated, filterable by
  category and by the kind of motion. Fewer weak entries than the big
  awards.
- **SiteInspire** — siteinspire.com (blocked, rate-limits) — curating
  since 2010; filters by style, type and subject, which is the fastest way
  to a specific brief.
- **Minimal Gallery** — minimal.gallery (text) — clean, content-first
  layouts. Good for hierarchy and whitespace, not for effects.
- **Seesaw** — seesaw.website (text) — daily, organised by industry (AI,
  crypto, portfolios), so it answers "what does this kind of company's
  site look like now".
- **Httpster** — httpster.net (text) — loud and current, less precious
  than the award sites.
- **Best Website Gallery** — bestwebsite.gallery (text).
- **Curated.design** — curated.design (text) — cross-indexed by style and
  industry.
- **Muzli** — muz.li (text) — daily aggregated feed; breadth over depth.

## Experimental and strange

Where to go when the brief is "unusual" and the awards all look the same.

- **Hoverstat.es** — hoverstat.es (blocked) — the reference for
  experimental, essayistic, non-commercial web work. Nothing else covers
  this territory.
- **Brutalist Websites** — brutalistwebsites.com (text) — raw HTML
  aesthetics, anti-polish, system fonts as a statement.
- **The Whimsical Web** — whimsical.club (text) — small personal sites
  with one delightful idea each. The antidote to the SaaS template.
- **Design Spells** — designspells.com (names) — collected micro-delights:
  the single detail in a product that made someone screenshot it.
- **Little Big Details** — littlebigdetails.com (text) — the older archive
  of the same idea, and still the deepest.
- **Are.na** — are.na (text) — user-built channels. Search a concept and
  read other people's collections; the least algorithmic source here.

## Landing pages and one-pagers

- **Land-book** — land-book.com (blocked) — very large, well filtered.
- **One Page Love** — onepagelove.com (text) — one-pagers with written
  teardowns attached.
- **Lapa Ninja** — lapa.ninja (blocked) — landing pages plus free design
  books.
- **Landingfolio** — landingfolio.com (text) — broken down by section
  (hero, pricing, testimonials), which is how you actually need it.
- **SaaS Landing Page** — saaslandingpage.com (text) — narrow by design.

## Product UI, flows and patterns

The best source for what a convention *is*; the worst for originality.

- **Mobbin** — mobbin.com (text) — screens and full flows from shipped
  iOS, Android and web apps, searchable down to the element. Depth needs
  an account.
- **Refero** — refero.design (text) — real product UI, searchable by
  screen and flow.
- **Page Flows** — pageflows.com (blocked) — recorded user flows, video.
  For onboarding, cancellation, paywalls.
- **UI Sources** — uisources.com (text) — flows with annotations.
- **Collect UI** — collectui.com (text) — daily, by component type.
- **Design Vault** — designvault.io (text) — patterns from real products.
- **Screenlane** — screenlane.com (blocked) — mobile UI updates over time.
- **Calltoidea** — calltoidea.com (text) — indexed by element.
- **UI Patterns** — ui-patterns.com (text) — a proper pattern library:
  what the pattern is, when it applies, why it works.
- **UX Patterns** — uxpatterns.dev (text) — newer, with code and
  accessibility notes per pattern.
- **Checklist Design** — checklist.design (text) — per-component
  checklists. Fast way to find what a design forgot.

## Technique, with source you can read

- **Codrops** — tympanus.net/codrops (text) — the single most useful
  source in this file. Every demo is downloadable, every tutorial explains
  the mechanism, and the Playground covers the effects that win awards.
- **CSS-Tricks** — css-tricks.com (text) — deep archive; check the date,
  the CSS platform has moved.
- **CodePen** — codepen.io (blocked) — search the technique, not the site;
  reach pens through a search engine.
- **The `awwwards` and `awwwards-inspired` GitHub topics** —
  github.com/topics/awwwards (blocked to curl, fine through the GitHub
  API) — rebuilds of sites that ship no source of their own, written
  specifically to reverse-engineer them.
- **Frontend Practice** — frontendpractice.com (text) — real sites set as
  rebuild exercises, with notes on what is hard about each.

## Motion and interaction craft

- **GSAP showcase** — gsap.com/showcase (names) — the effect plus the API
  that made it; the docs beside it are the mechanism in words.
- **Motion** — motion.dev (text) — examples and docs for the modern
  successor to Framer Motion.
- **Emil Kowalski** — emilkowal.ski and animations.dev (text) — the author
  of Sonner and Vaul on why an animation feels right, with numbers for
  duration and easing.
- **Rauno Freiberg** — rauno.me and interfaces.rauno.me (text) — the
  invisible details of interaction design, itemised. Read before building
  anything with a hover, a drag or a focus state.
- **Josh Comeau** — joshwcomeau.com (text) — long, exact articles on CSS
  and interaction, each with live playgrounds.
- **Build UI** — buildui.com (text) — React animation recipes with the
  reasoning shown.

## Typography

- **Typewolf** — typewolf.com (text) — fonts in use on real sites, site of
  the day, and pairing lists. Start here for "what typeface is that".
- **Fonts In Use** — fontsinuse.com (text) — indexed by industry, format
  and typeface, going back a century. The source for a period-correct
  choice.
- **Typographica** — typographica.org (text) — type reviews; why a face is
  good, not only that it is.

## Design systems and components

- **The Component Gallery** — component.gallery (text) — the same
  component across dozens of real design systems, each linked. The fastest
  way to see how a thing is normally built.
- **Design Systems Repo** — designsystemsrepo.com (text) — index of public
  design systems.
- **Adele** — adele.uxpin.com (text) — the other index, with pattern
  libraries.
- **Open UI** — open-ui.org (text) — research into component anatomy and
  semantics. Names the parts, which makes everything else searchable.
- **GOV.UK Design System** — design-system.service.gov.uk (text) — every
  pattern carries the user research behind it. Unmatched for forms.
- **Material Design 3** — m3.material.io, and **Apple HIG** —
  developer.apple.com/design (text) — platform conventions, and the
  argument for each.

## Evidence rather than taste

When these disagree with a gallery, these win.

- **Nielsen Norman Group** — nngroup.com (text) — usability research,
  decades of it, written plainly.
- **Baymard Institute** — baymard.com (text) — large-scale e-commerce and
  checkout research with benchmarks. The numbers are the point.
- **Laws of UX** — lawsofux.com (text) — heuristics with their citations
  attached.
- **Inclusive Components** — inclusive-components.design (text) — how to
  build each component so it actually works for everyone.
- **ARIA Authoring Practices Guide** — w3.org/WAI/ARIA/apg (text) — the
  canonical keyboard behaviour and semantics for every widget. Not
  optional reading for a custom control.
- **GoodUI** — goodui.org (text) — patterns with A/B test evidence.
- **Growth.design** — growth.design/case-studies (text) — teardowns of
  real products through behavioural psychology.
- **Deceptive Design** — deceptive.design (blocked) — the taxonomy of dark
  patterns. Read it to recognise what not to copy from a converting page.

## Brand, graphic and critique

For a visual idea that has not been on a website yet.

- **It's Nice That** — itsnicethat.com (text)
- **Eye on Design (AIGA)** — eyeondesign.aiga.org (text)
- **Creative Review** — creativereview.co.uk (blocked)
- **The Brand Identity** — the-brandidentity.com (text)
- **Brand New** — underconsideration.com/brandnew (text) — rebrand
  critiques; the comments are where the reasoning is.

## Mood and visual bookmarking

Deep and strange, and stripped of provenance. A starting point, never
proof that something works.

- **Cosmos** — cosmos.so (names)
- **Savee** — savee.it (names)
- **Are.na** — are.na (text) — the one with context attached.
- **Pinterest** — pinterest.com (names) — vast, and the least reliable
  attribution on this list.

## Historical

- **Web Design Museum** — webdesignmuseum.org (blocked) — 1991 to 2006,
  organised by year. Where a period style can be checked rather than
  imagined.
- **Wayback Machine** — web.archive.org (blocked from some networks; the
  JSON API `archive.org/wayback/available?url=<site>` answers where the
  front end does not) — earlier versions of any specific site. The best
  way to see how a design was arrived at, and what its team dropped.

## Handle with care

- **Dribbble** — dribbble.com, **Behance** — behance.net (blocked) — a
  shot is a drawing of an interface: no real content, no empty state, no
  error state, often never built. Take colour and mood; never take layout,
  density or feasibility.
- **Figma Community** — figma.com/community (blocked) — files you can open
  and measure, which is genuinely useful, mixed with a great deal of
  aspirational work that no engineer has ever costed.
- **Component snippet registries** — 21st.dev, reactbits.dev,
  ui.aceternity.com, uiverse.io (mostly text) — copy-paste effects. Useful
  for a mechanism, but this is precisely the pool the generic AI-built look
  is drawn from: gradient hero, glow border, marquee logos, animated
  beams. Take the technique if it fits; do not take the look.
